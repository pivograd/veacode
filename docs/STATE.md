# Состояние проекта

Дата: 15 октября 2026 года. Версия пакета: 0.1.0.

Реализован первый локальный прототип: сохранённые задачи, три CLI-адаптера,
статическая маршрутизация и продолжение из контрольных точек. Живой пилот через
OpenCode + DeepSeek прошёл полный цикл; подписочные маршруты требуют отдельной проверки.
Согласованный объём — в [ARCHITECTURE.md](ARCHITECTURE.md).

| Область | Текущее состояние |
|---|---|
| Контроллер | Этапы планирования, реализации, локальных проверок и ревью реализованы |
| Хранилище | SQLite, события, попытки, PID, блокировка рабочего каталога |
| Адаптеры | Claude Code, Codex, OpenCode с прямым DeepSeek API |
| Платный доступ | Только DeepSeek; шаблон выключен, локальный доступ разрешён пользователем |
| Интеграционный skill | Поставляется в репозитории, автоматической установки нет |
| Существующий Claude → Codex skill | Не изменялся |
| Бесплатные источники и денежные потолки | Отложены по решению пользователя |
| Windows | Python 3.12.10; локальные тесты временных репозиториев и процессов проходят |
| Ubuntu и Python 3.13 | Настроена CI-матрица; результат удалённого запуска ещё не зафиксирован |
| Реальные OpenCode + DeepSeek вызовы | План → исправление → проверки → ревью: `completed` |
| Реальные Claude/Codex вызовы | Пока не подтверждены в этой среде |
| Экономия подписок и времени пользователя | Не измерена |
| Пакет | Wheel и sdist собираются; конфигурация включена, runtime/ключи исключены |
| GitHub | `gh` видит pivograd, но вход возвращает HTTP 401; удалённый репозиторий не создан |
| Локальный Git | Инициализирован; запись `.git/index.lock` запрещена средой, коммит не создан |

Тесты используют подставные ответы и CLI, временные Git-репозитории и локальные процессы.
Это проверяет состояние, маршрутизацию, ограничения и восстановление, но не качество
реальных моделей, действительность входов, квоты или совместимость всех CLI-флагов.
В тестах и CI нет запросов к моделям и платных обращений.

## Выполненные прогоны

- **Живой DeepSeek-пилот**: задача `c42f11932f5a4032beafe2b0e3f0a39b`, OpenCode `1.19.0`,
  явно выбранный `deepseek-v4-pro`, прямой DeepSeek API. Основной маршрут намеренно
  отсутствует, а резерв выполняет все три модельных этапа. Итог `completed`, без
  переделок: исправлена функция, хэш исходных тестов сохранён, все три теста пройдены,
  ревью принято. Наблюдаемую модель CLI отдельно не сообщил; записана выбранная модель.
  Пилот подтверждает работу без Claude и переключение после ошибки доступности;
  он не имитирует ответ настоящего сервиса об исчерпании Max.
- Первая живая попытка `00eebc1ef11e4fd5867cc0b315a34b68` выявила дефект пилота:
  ожидаемый SHA-256 считался до преобразования LF→CRLF Windows. Исполнитель был
  остановлен после обнаружения; задача сохранена в `needs_reconciliation`.
  Хэш теперь считается по реально записанным байтам, добавлен офлайн-регрессионный тест.
  Также проверки Python используют новый временный путь bytecode-кэша, чтобы
  одинаковые размер и timestamp правки не подменяли текущий код устаревшим `.pyc`.
- Итоговая локальная проверка после живого пилота: **94 теста**, 93 пройдено и один Unix-тест пропущен
  на Windows; `ruff check` и `ruff format --check` пройдены. Wheel и sdist собраны.
  Skill проходит официальный `quick_validate.py`. Удалённая CI-матрица ещё не запускалась.
- Скрипт подключения Git проверен PowerShell-парсером. Добавлено доверие к точному
  корню проекта на время каждого вызова Git, чтобы пользователь мог открыть Git-каталог,
  созданный sandbox-аккаунтом; глобальный `safe.directory` и ACL не меняются.
  На воспроизведённой проверке чужого владельца: без исключения Git вернул 128,
  с точным путём — 0. Создание репозитория и push ожидают пользовательского терминала.
- `examples/offline_demo.py`: задача `6d3611c479bc43fe812345605c132c2d` завершена;
  4 попытки с имитацией пустого Max, реальное исправление файла локальным исполнителем,
  три настоящих unit-теста. Это симуляция ответов агентов, а не вызов провайдера.
- Claude Code `2.1.300`: штатный вход Max подтверждён. Живой запрос только на чтение
  дошёл до init (`claude-opus-5-5`), затем повторов API с неизвестной ошибкой и тайм-аута
  45 секунд. Финального ответа и usage нет; стоимость/расход подписки неизвестны.
- Codex CLI `0.162.1`: штатный вход ChatGPT подтверждён. Проба `gpt-6.1-sol` остановилась
  до вызова модели: CLI требует запись native `CODEX_HOME/installation_id`, а текущая
  среда даёт только чтение `.codex`. `--ephemeral` эту обязательную запись не отменяет.
  [Код установленной версии](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/core/src/installation_id.rs).
- OpenCode `1.19.0`: установлен локально под `.venv/opencode`; native Windows baseline
  binary запускается. Проверены `--version`, `run --help` и `debug config --pure` с
  конфигурацией адаптера. Живой вызов с локальным ключом теперь проверен (см. выше).
- `https://api.deepseek.com/models` отвечает HTTP 401 на запрос Python без credentials:
  сетевой маршрут доступен, требуется ключ.
- Для этой машины создан игнорируемый `veacode.local.toml` с путём к локальному OpenCode.
  После предоставления ключа пользователем в нём включён `allow_deepseek = true`;
  значение ключа в конфигурацию не включено.

Следующие шаги: подключить приватный GitHub через `scripts/connect-github.ps1` из
обычного PowerShell, затем проверить подписочные маршруты и переключение между
разными harness на реальных задачах. Скрипт не меняет ACL или политики среды;
перед коммитом проверяет тесты, игнорирование ключа и допустимые пути публикации.

После живого пилота сюда нужно добавить версии CLI, выбранные модели, идентификатор
задачи, результат проверок, проверенные сценарии остановки и оставшиеся ограничения.
Продолжение после аварии и экономия на репрезентативных задачах всё ещё требуют
отдельного пилота. Расходы OpenCode из каталога считаются оценкой, а не счётом DeepSeek.
